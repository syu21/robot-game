# 出撃仕様（/explore）

最終更新日: 2026-05-17

## 1. エンドポイント
- 実行: `POST /explore`
- 主入力: `area_key`
- エリア:
  - `layer_1`
  - `layer_2`
  - `layer_2_mist`
  - `layer_2_rush`
  - `layer_3`
  - `layer_4_forge`
  - `layer_4_haze`
  - `layer_4_burst`
  - `layer_4_final`（第4層3ボス撃破後の最終試験）
  - `layer_5_labyrinth`
  - `layer_5_pinnacle`
  - `layer_5_final`（第5層2ボス撃破後の最終試験）

## 2. 前提チェック順序
1. ログイン済み
2. `area_key` 妥当性
3. 層解放状態 (`max_unlocked_layer`)
4. 出撃機体存在（active robot）
5. 管理者判定
6. 研究ブースト所持かつ自動使用ONなら1回分を自動消費してCT判定をスキップ
7. 共通CT判定

## 3. CT仕様（共通）
- 一般ユーザー: 40秒
- 新規ブースト対象（登録後72時間）: 20秒
- 課金ブースト中（14日）: 20秒
- 管理者: 0秒
- 研究ブースト所持かつ自動使用ON: その出撃だけ1回分を消費し、CTを0秒として即出撃する
- 優先順位: 管理者 -> 研究ブースト -> 課金ブースト -> 新規ブースト -> 通常
- 課金ブースト中でも研究ブーストは消費でき、なくなったら課金ブーストの20秒へ戻る
- 重要: UI表示とサーバ判定は同一ヘルパーで一致させる

### 3.2 出撃前の所持枠表示
- `/home` の出撃ボタン付近に `パーツ所持 X/Y` を表示する
- 所持数が上限の80%以上なら注意表示、上限到達なら強めの注意表示にする
- 固定ナビのパーツ導線にも、邪魔にならない範囲で `X/Y` を表示する
- 表示値は `part_instances.status='inventory'` の件数とユーザーの所持上限を使う

### 3.1 研究ブースト
- `users.research_boost_charges`: 所持回数、上限3
- `users.research_boost_auto_use_enabled`: 自動使用ON/OFF。初期値はON
- `users.lab_small_boost_count` / `users.lab_small_boost_until` は旧時間制の互換列として残すが、出撃判定・UIでは参照しない
- `/admin/release` の `研究ブースト` を一般公開すると、ホームに `研究ブースト X / 3` と回数説明を表示する
- ホーム下部にON/OFFボタンを表示し、ONのときだけ `POST /explore` 時に自動で1回分を消費する
- OFF中は所持回数を温存し、既存のCT判定を使う
- 管理者はもともとCT0秒のため、研究ブーストを消費しない
- 入手は日ごとに `デイリーログイン / 実験室参加 / Xシェア` 各1回まで
- 実験室参加は、レース参加、投稿ロボ閲覧、試作機投稿、展示閲覧の初回で付与する
- Xシェアはホームの `Xでシェアして研究ブースト +1回` から投稿画面を開いた時点で付与する
- Xシェア本文には `/share/robot/<robot_instance_id>` を含め、共有ページのOGP画像に現在機体の合成画像を使う

## 4. 戦闘仕様
- 実装正本は `docs/BATTLE_SPEC.md`
- ターン上限: 8
- 両者生存のまま8ターン到達時は残HP割合の高い側が勝利
- 残HP割合が同率なら敗北
- 連戦: 週間環境などの条件で発生可
- tier1救済: 通常戦で連続MISS時に救済ヒット
- 敵特性(trait)の軽補正あり

## 5. ボス抽選
- 基本出現率: 0.5%
- エリア対応ボスのみ抽選対象
- 第1層固定ボス未撃破ユーザーは、第1層探索10回目以降で既存チュートリアル導線が未発動の場合のみ、即戦闘ではなく第1層ボス警報を確定付与する
- layer_2/3 は NPCボス統合抽選（実装時設定に従う）
- layer_4_forge / haze / burst は各エリア専用の固定ボスを持つ
- `layer_4_final` は第4層3ボス撃破後に解放される最終試験エリアで、`アーク=ゼロ` 固定
- `layer_5_labyrinth` / `layer_5_pinnacle` は各エリア専用の固定ボスを持つ
- `layer_5_final` は第5層2ボス撃破後に解放される最終試験エリアで、`オメガフレーム` 固定

## 6. 報酬決定
- コイン: 勝敗・環境補正に応じて加算
- パーツドロップ: 予算制御あり（探索単位で上限）
- 進化コア:
  - 低確率ドロップを維持
  - 勝利ごとの保証進捗を別管理
  - ゲージ満了で保証付与
  - layer_2/3 の NPCボス撃破では追加報酬として `進化コア x1`
  - 監査: `audit.core.drop`
- 第4層の育成傾向:
  - `layer_4_forge`: 耐久・防御寄り
  - `layer_4_haze`: 命中・安定寄り
  - `layer_4_burst`: 攻撃・会心寄り
  - `layer_4_final`: 最終試験（複合）
- 第5層の育成傾向:
  - `layer_5_labyrinth`: 耐久・命中・安定寄り
  - `layer_5_pinnacle`: 攻撃・会心・速攻寄り
  - `layer_5_final`: 最終試験（思想完成）
- 第1層固定ボス初突破:
  - 既存ボスDECOR `boss_emblem_aurix` に加え、初突破DECOR `layer1_clear_emblem_001` とコイン `+100`
  - 二重付与は `layer1_first_clear_reward_claimed` で防止

## 7. 戦利品表示（battle結果）
- 前面は最小表示:
  - 獲得コイン
  - ドロップ結果（なしなら `戦利品なし`）
- `進化コア保証` や `ボス報酬` は短い結果行で区別して表示
- battle結果の followup は `結果 / 戦利品 / 次の行動` を先頭に寄せ、敵情報と詳細ログは折りたたみへ退避してスマホでも再出撃しやすくする
- 下部の `次の行動` はカード表示にし、`もう一度出撃 / 入手したパーツを見る / 基地へ戻る` を押しやすく出す
