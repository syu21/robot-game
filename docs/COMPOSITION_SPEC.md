# 編成・強化・進化仕様

最終更新日: 2026-04-10

## 1. 範囲
- 所持パーツ一覧: `/parts`
- ロボ編成: `/build`, `/build/confirm`
- 機体整備: `/robots/<id>/maintenance`
- パーツ強化: `/parts/strengthen`（`/parts/fuse`互換）
- 進化合成: `/parts/evolve`

## 2. 所持パーツ一覧
### 2.1 表示方針
- 装備中と所持中を同じ一覧で比較できる
- 在庫上限は `今すぐ使える所持枠`（`part_instances.status='inventory'`）にのみ適用する
- 上限超過で入手した個体は `overflow` 扱いで保管し、報酬は消失させない
- 前面に出す情報は `画像 / パーツ名 / 部位 / レアリティ / +値 / 6ステ / 装備中かどうか`
- `hp / atk / def / spd / acc / cri` などの内部キーはUIへ出さない
- 旧在庫などの内部都合ラベルは出さず、必要なときだけ `保管パーツ` として別扱いにする

### 2.2 比較情報
- 6ステはカード内グリッドで常時表示する
- `総合値` と `注目2能力` を補助表示する
- 装備中個体はバッジで明示し、`見比べる` 選択には含められる
- `破棄` は所持中個体だけを対象にし、装備中は誤って消えないようにする
- 保管中個体は別セクションで閲覧でき、選択して `所持へ戻す` 操作ができる
- ただし、強化・進化・編成の候補には混ぜない

### 2.3 絞り込み
- 部位フィルターを持つ
  - `すべて / 頭 / 右腕 / 左腕 / 脚`
- クエリパラメータ `part_type` で保持する
- ソートを持つ
  - `おすすめ順 / 新しい順 / 古い順 / 総合値が高い順 / +値が高い順 / レアリティ順 / 部位順`
- クエリパラメータ `sort` で保持する
- ページ送りと併用しても条件が落ちない

### 2.4 在庫表示
- ホームでは `所持 X/Y | 保管 Z` で表示する
- `保管 Z` は `overflow` 個体と旧 `user_parts_inventory` を合算する
- 保管中の個体パーツは `/parts` から選択して所持へ戻せる
- 所持一覧の主操作は `見比べる / 破棄` に分け、`整理` のような曖昧な文言は使わない
- 旧 `user_parts_inventory` の破棄UIは従来どおり維持する

## 3. ロボ編成
### 3.1 必須・任意
- 必須: `HEAD`, `RIGHT_ARM`, `LEFT_ARM`, `LEGS`
- 任意: `DECORATION`

### 3.2 比較表示
- 編成候補カードは `現在装備との差分` を主役にし、初期表示では `パーツ名 / +値 / 個体ID / 総合差分 / 注目2能力差分` を優先する
- `6ステ実数 / レアリティ / 同名内の並び情報` は `詳細を開く` にまとめ、カードを縦に伸ばしすぎない
- プレビュー比較（組み立て中 vs 現装備）は維持する
- セットボーナスは `発動中/未発動 / 同属性パーツ 4部位で発動 / 何が上がるか` をプレビューと現装備の両方で見せる
- 属性ごとの効果一覧は `/guide` でも確認できるようにする

### 3.3 合成画像
- 画像サイズ: 128x128 PNG
- レイヤー順: `LEGS -> HEAD -> RIGHT_ARM -> LEFT_ARM -> DECORATION`
- オフセット: `robot_parts.offset_x/y` を使用

### 3.4 保存
- `robot_instances` + `robot_instance_parts` に保存
- 保存枠超過時は保存ブロック

### 3.5 小型ユーザー機体アイコン
- `robot_instances.icon_32_path` に 32x32 の小型機体画像を保持する
- 生成タイミングは `/build/confirm` の編成確定時を正とし、同時に `users.active_robot_id` を更新する
- 未生成時だけ `composed_image_path` からオンデマンド再生成する
- 切り抜きは `HEAD` が見やすい上寄せの正方形を優先し、機体全体を縮小しすぎない
- `DECORATION` を積んでいる場合は、本体を隠さない範囲で小さく残す
- ユーザー表示では、この `icon_32_path` を `主役の小ロボ画像` として使う
- 補助アバターは `手動画像 -> Google画像 -> seed生成アイコン` の順で選ぶ
- 機体未所持時だけ `主役の小ロボ画像` は `初期ノーマルロボ顔` の既定画像へフォールバックする
- 用途:
  - `/ranking` の user系ランキング
  - `/home` のヘッダー、`今週のランキング`、`今週のMVP`
  - `/world` の MVP 表示
  - `/records` のユーザー表示
  - `/comms/world`, `/comms/rooms` のユーザー表示

### 3.6 機体整備
- 編成済みロボを壊さずに `HEAD / RIGHT_ARM / LEFT_ARM / LEGS / DECOR` を1部位ずつ差し替える
- 前面文言は `機体整備` に統一し、単なる `交換` ではなく整備 / 手入れの文脈で見せる
- 候補ごとに `総合値差分 / 6ステ差分 / 注目能力 / 思想変化` を確認してから確定できる
- 確定時は `robot_instance_parts` 更新後に `composed_image_path / icon_32_path` を再生成し、ホーム・ランキング・小型アイコン表示まで即時反映させる
- 監査は `audit.robot.maintenance` を使い、`robot_instance_id / changed_slots / before_part_ids / after_part_ids / stat_delta / power_delta` を残す
- `思想` はラベルだけでなく `どんな戦い方になりやすいか` の短い補助文つきで表示する

## 4. DECOR表示方針
- DECORはバッジ的に小型表示（本体中心を隠さない）
- 所有DECORのみ選択可
- `なし` は常時選択可

## 5. パーツ強化
### 5.1 導線
- 正規: `/parts/strengthen`
- 互換: `/parts/fuse`（同処理）

### 5.2 仕様
- ベース1 + 素材2
- 成功率100%
- 上昇量は常に +1固定
- 対象条件は「同名 + 同レアリティ」（+値違い可）
- 強化候補は「成立可能なグループ」のみ表示
- 素材自動選択時は安全制約あり（装備中素材消費禁止など）

### 5.3 比較表示
- ベース候補は個体単位で選ぶ
- 画面内で `強化前 -> 強化後` の差分を6ステで見せる
- 同時に、素材として消える2個も確認できる
- 装備中ベースを使う場合は、素材が所持中から出ることを文言で明示する
- 保管中個体は強化候補に混ぜず、保管のため成立していない組み合わせがある場合は `/parts` へ戻す案内を出す
- 失敗時は `失敗` 表示と理由文を結果面に残し、無反応に見せない

### 5.4 監査
- `audit.fuse`
- payloadに成功可否、消費ID、増分などを保持
- `まとめて強化` と `倉庫整理合成` でも既存 `audit.fuse` を使い、payload に `batch_mode: true`, `batch_count`, `power_delta_estimate` を追加する
- `倉庫整理合成` は補助イベントとして `audit.fuse.batch_preview`, `audit.fuse.batch_execute` を追加し、`mode: "warehouse_batch"`, `group_count`, `fuse_count`, `consumed_part_ids`, `result_part_ids`, `total_coin_cost`, `total_material_count` を残す

### 5.5 まとめて強化
- `/parts/strengthen` に `まとめて強化` ブロックを追加する
- ルール自体は個別強化と同じく `ベース1 + 素材2 -> +1固定` を繰り返すだけで、別ルールは作らない
- 対象は `同名 / 同レア` グループごと
- 装備中素材は自動消費しない
- 実行前に `残る個体 / 消える個体数 / 強化後の +値 / 総コイン` を明示する
- 実行後は `何回実行したか / 何が消えたか / +値がどうなったか` を結果面�
