# 編成・強化・進化仕様

最終更新日: 2026-05-18

## 1. 範囲
- 所持パーツ一覧: `/parts`
- ロボ編成: `/build`, `/build/confirm`
- 機体整備: `/robots/<id>/maintenance`
- パーツ強化: `/parts/strengthen`（`/parts/fuse`互換）
- 進化合成: `/parts/evolve`

## 2. 所持パーツ一覧
### 2.1 表示方針
- 装備中と所持中を同じ一覧で比較できる
- 在庫上限は `part_instances.status='inventory'` の所持枠にのみ適用する
- 上限超過で入手した新規個体は自動売却し、`coins` に変換する
- 戦利品画面では `自動売却 +NNコイン` と短く明示する
- 前面に出す情報は `画像 / パーツ名 / 部位 / レアリティ / +値 / 6ステ / 装備中かどうか`
- `hp / atk / def / spd / acc / cri` などの内部キーはUIへ出さない
- 旧在庫や旧 `overflow` は前面に出さず、市場公開時の一括売却対象として扱う

### 2.2 比較情報
- 6ステはカード内グリッドで常時表示する
- `総合値` と `注目2能力` を補助表示する
- 注目能力が出る画面では `現在値は今の強さ、注目能力は伸びやすい傾向です。迷ったら両方を見て選んでください。` と補足する
- 装備中個体はバッジで明示し、`見比べる` 選択には含められる
- `破棄` は所持中個体だけを対象にし、装備中は誤って消えないようにする
- 自動売却済み個体は強化・進化・編成の候補には混ぜない

### 2.3 絞り込み
- 部位フィルターを持つ: `すべて / 頭 / 右腕 / 左腕 / 脚`
- クエリパラメータ `part_type` で保持する
- ソートを持つ: `おすすめ順 / 新しい順 / 古い順 / 総合値順 / +値順 / レアリティ順 / 部位順`
- クエリパラメータ `sort` で保持する
- ページ送りと併用しても条件が落ちない

### 2.4 在庫表示と保護
- ホームでは出撃ボタン付近に `パーツ所持 X/Y` を表示する
- 80%以上は注意表示、満杯は強めの注意表示にする
- 固定ナビのパーツ導線にも邪魔にならない範囲で `X/Y` を表示する
- 所持一覧の主操作は `見比べる / 破棄` に分け、曖昧な文言は使わない
- 保護中のパーツは `破棄 / 強化素材 / 進化素材` の対象にしない
- 保護説明は `破棄` と `素材消費` に統一し、廃止済みの操作名は使わない
- 所持パーツ画面下部の `基地へ / パーツ強化へ / 廃品市場へ` は、gapを取り、スマホでも押しやすいボタン風リンクにする

## 3. ロボ編成
### 3.1 必須・任意
- 必須: `HEAD`, `RIGHT_ARM`, `LEFT_ARM`, `LEGS`
- 任意: `DECORATION`

### 3.2 比較表示
- 編成候補カードは `現在装備との差分` を主役にする
- 初期表示では `パーツ名 / +値 / 個体ID / 総合差分 / 注目2能力差分` を優先する
- `6ステ実数 / レアリティ / 同名内の並び情報` は `詳細を開く` にまとめる
- プレビュー比較（組み立て中 vs 現装備）は維持する
- セットボーナスは `発動中/未発動 / 同属性パーツ 4部位で発動 / 効果` を見せる
- 属性ごとの効果一覧は `/guide` でも確認できるようにする

### 3.3 合成画像
- 画像サイズ: 128x128 PNG
- レイヤー順: `LEGS -> HEAD -> RIGHT_ARM -> LEFT_ARM -> DECORATION`
- オフセット: `robot_parts.offset_x/y` を使用

### 3.4 保存
- `robot_instances` + `robot_instance_parts` に保存
- 保存枠超過時は保存ブロック

### 3.5 小型ユーザー機体アイコン
- `robot_instances.icon_32_path` に 32x32 の小型機体画像を保持する
- 生成タイミングは `/build/confirm` の編成確定時を正とし、同時に `users.active_robot_id` を更新する
- 未生成時だけ `composed_image_path` からオンデマンド再生成する
- 切り抜きは `HEAD` が見やすい上寄せの正方形を優先する
- `DECORATION` を積んでいる場合は、本体を隠さない範囲で小さく残す
- 用途は `/ranking`, `/home`, `/world`, `/records`, `/comms/world`, `/comms/rooms` のユーザー表示

### 3.6 機体整備
- 編成済みロボを壊さずに `HEAD / RIGHT_ARM / LEFT_ARM / LEGS / DECOR` を1部位ずつ差し替える
- 前面文言は `機体整備` に統一する
- 候補ごとに `総合値差分 / 6ステ差分 / 注目能力 / 思想変化` を確認してから確定できる
- 確定時は `robot_instance_parts` 更新後に `composed_image_path / icon_32_path` を再生成する
- 監査は `audit.robot.maintenance` を使う

### 3.7 ロボ分解
- 分解で戻る対象は、既存分解仕様に従って `HEAD / RIGHT_ARM / LEFT_ARM / LEGS / DECORATION` のうち実際に所持パーツへ戻す個体とする
- 実行前に `現在の所持パーツ数 + 分解で戻るパーツ数` を計算する
- 上記が所持上限を超える場合は分解不可とし、`robot_instances / robot_instance_parts / part_instances` を変更しない
- エラー時は `所持パーツ / 廃品市場 / ロボ一覧` へ戻れる導線を出す
- 監査は新規イベント `audit.robot.decompose.blocked` に `robot_instance_id / inventory_count / inventory_limit / return_count / reason` を残す

## 4. DECOR表示方針
- DECORはバッジ的に小型表示（本体中心を隠さない）
- 所有DECORのみ選択可
- `なし` は常時選択可

## 5. パーツ強化
### 5.1 導線
- 正規: `/parts/strengthen`
- 互換: `/parts/fuse`（同処理）

### 5.2 仕様
- ベース1 + 素材2
- 成功率100%
- 上昇量は常に +1固定
- 対象条件は `同名 + 同レアリティ`（+値違い可）
- Rベースのみ補助ルールあり: `R + 対応N素材2 -> r_assist_points +50`、100到達で `+1`
- 強化候補は成立可能なグループのみ表示
- 素材自動選択時は、保護中・装備中・保管中の素材を消費しない
- `+3 -> +4` は、同名同レアの素材2個など成立条件を満たせば実行できる
- 古い `+3` 上限判定は使わない。上限は `MAX_PART_PLUS` を正とする

### 5.3 比較表示
- ベース候補は個体単位で選ぶ
- 画面内で `強化前 -> 強化後` の差分を6ステで見せる
- 同時に、素材として消える2個も確認できる
- 装備中ベースを使う場合は、素材が所持中から出ることを文言で明示する
- 対象は所持中個体に限定し、自動売却済みや旧 `overflow` 個体は候補に混ぜない
- 失敗時は理由文を結果面に残し、無反応に見せない
- ボタンが押せない場合は、素材不足、保護中、装備中、保管中、最大強化済みなどの可能性を画面内で補足する

### 5.4 監査
- `audit.fuse`
- payloadに成功可否、消費ID、増分などを保持
- R補助強化時は payload に `material_mode`, `assist_before`, `assist_gain`, `assist_after`, `assist_threshold` を保持する
- `まとめて強化` と `倉庫整理合成` でも既存 `audit.fuse` を使い、payload に `batch_mode: true`, `batch_count`, `power_delta_estimate` を追加する
- `倉庫整理合成` は補助イベントとして `audit.fuse.batch_preview`, `audit.fuse.batch_execute` を追加する

### 5.5 まとめて強化
- `/parts/strengthen` に `まとめて強化` ブロックを追加する
- ルール自体は個別強化と同じく `ベース1 + 素材2 -> +1固定` を繰り返すだけで、別ルールは作らない
- 対象は `同名 / 同レア` グループごと
- 装備中素材は自動消費しない
- 実行前に `残る個体 / 消える個体数 / 強化後の +値 / 総コイン` を明示する
- 実行後は `何回実行したか / 何が消えたか / +値がどうなったか` を結果面に残す

### 5.6 倉庫整理合成
- `/parts/strengthen` に `倉庫整理合成` 導線を追加する
- `まとめて強化` との違いは、1種類単位ではなく `所持中全体` を走査して成立分を一覧プレビューする点
- 対象は `part_instances.status='inventory'` の所持中個体だけで、装備中 / 売却済み / 強化対象外個体は候補に混ぜない
- 実行前プレビューを必須にする
- ベース選択優先は `装備中ベース -> +値が高い個体 -> 作成日時が古い個体 -> id` の順で固定する

## 6. 進化合成
### 6.1 仕様
- Nパーツ + 進化コア1個 -> 対応するRパーツ
- 進化先Rマスタ未登録ならエラー復帰

### 6.2 引き継ぎ
- `plus` 維持
- `w_hp..w_cri` 維持
- 装備中個体を進化合成した場合は、同じ `part_instance` のまま進化先へ置換し、対応する `robot_instance_parts.*_key` と `robot_instances.composed_image_path / icon_32_path` を即時再生成する

### 6.3 比較表示
- 候補カード上で `進化前 -> 進化後` を見比べられる
- 必須表示は `パーツ名 / 部位 / レアリティ / +値 / 6ステ`
- `強化値と個体性能はそのまま引き継がれます` を短く補助表示する

### 6.4 監査
- `audit.part.evolve`

## 7. 表示名
- 優先順位: `display_name_ja` -> 自動生成名 -> 旧name列 -> part_key
