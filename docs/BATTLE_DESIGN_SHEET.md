# 戦闘・経済 設計シート

最終更新日: 2026-04-07

注記:
- このファイルは設計意図と調整方針のメモです
- 現在の実装仕様は `docs/BATTLE_SPEC.md` を正本とします

## 1. 設計目的
- 短時間で1周できるテンポ
- 初見でも理解しやすい結果画面
- 研究余地は残すが前面情報は最小化

## 2. 戦闘テンポ
- 基本: 1出撃1戦
- 例外: 特定環境で連戦あり
- 1戦の上限: 8ターン
- 目標ターン帯: 3〜5ターン
- 第4層は上限を変えず、通常敵から `layer_3` 固定ボス級を超える強度にする
  - チュートリアル終了後の本番帯として、全体火力と耐久を一段引き上げる
  - そのうえで敵の役割差で実質ターン数を分岐させる
  - forge: やや長期戦
  - haze: MISSで伸びやすい
  - burst: 短期高刺激
- 第5層も上限は変えず、4層よりさらに高圧な終盤帯として勝ち方の軸を複数化する
  - labyrinth: 安定して抜けるか
  - pinnacle: 最速で抜けるか
  - omega: 何を捨てて何を残すか

## 3. 勝敗体験
- 勝利時: 戦利品カードを最短で確認
- 敗北時: 理由が分かるログを残し再挑戦導線を明示
- 重要: 通常戦は静か、ボス撃破時のみ演出を強める
- 第4層の役割は「背水一強をナーフではなく相性分化で崩すこと」
- 耐久 / 命中 / 爆発 / 安定にそれぞれ勝ち場所を作る

## 3.1 型相性
- `安定 / 爆発 / 背水` は三すくみとして戦闘ダメージに軽補正をかける
- 相性: `爆発 > 背水`, `背水 > 安定`, `安定 > 爆発`
- 初期倍率: 有利 `x1.12`, 不利 `x0.92`, 五分/不明 `x1.00`
- 対象: 通常出撃、ボス戦、今週のチャンプ戦
- 補正対象は攻撃ダメージのみ。命中、会心、防御率にはまだ入れない
- 戦闘ログには開始時に1回だけ `型相性` 行を出す
- チャンプ戦は挑戦前カードで `有利 / 不利 / 五分 / 不明` を表示する

## 4. 戦利品UI方針
前面表示は以下のみ:
- 獲得コイン
- ドロップ結果（なしの場合は `戦利品なし`）
- 進化コア保証やボス報酬の短い結果表示
- `もう一度出撃` は最重要CTAとしてスマホ初期表示に入りやすい位置へ置く
- 敵情報や詳細ログは再出撃より後ろへ退避し、必要時だけ開く

前面から外す情報:
- 内部補正係数
- 出現率/ドロップ率の数式寄り表示
- 構成メモ等の分析項目

## 4.1 戦闘演出補足
- ダメージ数字はスマホで読める大きさを優先し、`HIT / CRIT / MISS / BLOCK` の違いが一目で分かるようにする
- 戦闘アニメ再生中は結果の `WIN / LOSE` を先見せしない。ネタバレを抑え、スキップ時だけ即結果へ進める

## 5. ボス戦方針
- 出現率 0.5% を基準
- 固定ボスは層進行に紐づけ
- 固定ボス/エリアボス報酬は DECOR 中心
- NPCボスは進化コア報酬あり
- SYSTEM投稿はボス撃破時のみ
- 第4層は 3サブエリア + 最終試験で型の理解を学ばせる
- 第5層は「型を誇る層」として、週環境 / 記録 / 展示へ接続する前提で設計する
- 第5層の価値は単純な高難度ではなく、安定記録と最速記録の両方を立てられること

## 6. 成長導線との接続
- 強化: `ベース1 + 素材2 -> +1固定`
- 進化: N + 進化コアでR化
- 保証: 勝利の積み上げで進化コア保証進捗が前進
- 編成: 4部位 + DECORで役割調整
- チャンプ初回撃破: そのチャンプ個体につき進化コア x1
- チャンプ日次撃破: 日本時間1日1回だけ追加コイン

## 7. ログ方針
- MISS/0ダメは抽象カテゴリで説明
- 詳細数式は常時表示しない（必要時のみ詳細へ）
- 監査は `audit.*` で別保存

## 8. 安定性要件
- CT表示とサーバ判定は一致
- JSエラー時でも白画面を避ける
- overlay演出はページ跨ぎで残留させない

## 9. 型相性シミュレーション方針
- 実戦導線を壊さずに型相性を検証するため、`services/balance_simulator.py` と `tools/run_balance_simulation.py` を開発用の純シミュレーション基盤として持つ
- 検証は `鉄壁 / 安定 / 命中 / 会心 / 爆発 / 背水 / バランス` の7型を対象にし、各型3テンプレ以上の群平均で見る
- 戦闘条件は本番と同じく `8ターン上限` を使い、時間切れは残HP割合判定まで含めて再現する
- 先手条件は `FIXED / RANDOM_FIRST / SPD_FIRST` の3モードで比較し、先手バイアスと型相性を切り分けて確認する
- `今週のチャンプ戦` は検証結果を踏まえて `RANDOM_FIRST` を採用し、先手固定だけで理不尽感が出にくい条件を使う
- チャンプ戦前の重点指標として `後手勝率 / 後手平均生存ターン / 後手逆転率 / 初手被弾後勝率 / 初手クリ被弾後勝率 / 平均残HP割合` を見る
- 理想勝率は有利側 `55〜65%`、強め相性でも `70%前後` までを目安とし、`75%超` は危険対面として明示する
- 目標は万能最強を作ることではなく、`周回向き / ボス向き / 記録向き / 模擬戦向き` の用途差を確認すること
- CLI 例:
  - `python3 tools/run_balance_simulation.py --n 1000`
  - `python3 tools/run_balance_simulation.py --pair tank burst --n 5000`
  - `python3 tools/run_balance_simulation.py --mode all --pair tank burst --n 5000`
  - `python3 tools/run_balance_simulation.py --export csv --output tmp/balance_matrix.csv`
